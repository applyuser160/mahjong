## 1. 向聴数計算 & スーツルックアップテーブル (LUT)

### 概要
一般手（4面子1雀頭）の向聴数計算において、バックトラッキング探索による再帰探索のオーバーヘッドを完全に排除するため、**色別ルックアップテーブル（Suit LUT）** を採用しています。

### スーツ表現とビットパッキング
萬子・筒子・索子の各9枚の牌数は 0〜4 です。各スートの状態は以下のハッシュ値またはコンパクト配列として表現されます。
- `build.rs` により、全パターン（約 4^9 = 262,144 通りから牌の総数制限 14 枚以下に絞り込んだもの）について、以下の情報を事前計算：
  - 各面子数（順子・刻子）および雀頭有無の組み合わせ
  - 各スート単体での最大面子・面子候補数
- 向聴数判定時は、萬子・筒子・索子・字牌のテーブル引き結果を合成するだけで、わずか数ナノ秒で一般手の向聴数を算出します。

### 特殊役判定
- **七対子向聴数**: 対子数 $P$ と異種牌数 $K$ から算定：
  $$\text{Shanten}_{\text{chitoi}} = 6 - P + \max(0, 7 - K)$$
- **国士無双向聴数**: 13種の么九牌の所持種類数 $T$ と么九牌の対子有無 $H$ から算定：
  $$\text{Shanten}_{\text{kokushi}} = 13 - T - H$$
- **最終向聴数**:
  $$\text{Shanten} = \min(\text{Shanten}_{\text{normal}}, \text{Shanten}_{\text{chitoi}}, \text{Shanten}_{\text{kokushi}})$$

## 2. SIMD ベクトル化 (AVX2 / SWAR)

### スーツキーのエンコード高速化
手牌カウント配列（34要素の牌数配列）からスートごとのキーを抽出・変換する処理において、AVX2命令（`_mm256_*`）または SWAR (SIMD Within A Register) を活用しています。

- 9要素の `u8` スライスを SIMD レジスタにロードし、基数変換（基数5の進数表現など）を並列乗算・加算で一括計算します。
- スカラー実装と比較して、キー抽出のレイテンシを約 60% 削減しています。

### 七対子判定のベクトル集計
- 34種の牌数配列に対して `_mm256_cmpeq_epi8` 等を用いて、牌数 2 以上の出現回数（対子数）および牌数 1 以上の出現回数（種類数）をブランチレス（条件分岐なし）で並列集計します。

## 3. 有効牌・受入れ探索と枝刈り

### 有効牌判定の基本原理
現在の手牌 $H$（13枚）に対し、牌 $T \in \{1 \dots 34\}$ を仮想的にツモった手牌 $H + T$ において：
$$\text{Shanten}(H + T) < \text{Shanten}(H)$$
が成り立つ牌 $T$ を**有効牌（受入れ牌）**と定義します。

### 枝刈り（Pruning）最適化
全34種を愚直に探索する代わりに、以下の枝刈りを適用：
1. **未所持かつ隣接牌のない孤立字牌・数牌のスキップ**:
   - 順子や対子を形成し得ない牌は向聴数を減らせないため、探索対象から除外。
2. **残り枚数ゼロ牌の除外**:
   - 自分の手牌＋捨て牌＋ドラ表示牌で既に4枚見えている牌は受入れ枚数 0 としてスキップ。

## 4. 役判定 & ゼロアロケーション (YakuSet)

### ビットマスク `YakuSet`
麻雀の役（立直、断幺九、平和、一盃口、混一色、三色同順、役満各種など全40種以上）の判定結果を、64ビット整数1つのビットマスク（`YakuSet`）として保持します。

```rust
#[derive(Clone, Copy, Debug, PartialEq, Eq)]
pub struct YakuSet(u64);

impl YakuSet {
    pub const RIICHI: u64 = 1 << 0;
    pub const TANYAO: u64 = 1 << 1;
    pub const PINFU: u64 = 1 << 2;
    // ...
}
```

### ゼロアロケーション（Zero Allocation）設計
役判定処理のホットパス（毎秒数百万回の打牌候補評価時）において、ヒープ確保（`Vec` や `HashMap`）を一切発生させない設計となっています。
- 面子分解の候補列挙には `arrayvec::ArrayVec` や `smallvec::SmallVec` を使用し、スタック領域のみで完結。
- 符計算・飜数集計もビット演算と定数テーブル引きにより極限まで最適化。

## 5. 局収支期待値 (EV) 探索 & Rayon 並列処理

### 打牌候補の局収支評価式
14枚の手牌から各打牌 $D_i$ を選択したときの局収支期待値 $EV(D_i)$ は、打牌後の有効牌受入れ・和了率・期待打点・放銃リスクから算出されます：

$$EV(D_i) = P_{\text{win}}(D_i) \times \text{Score}_{\text{win}}(D_i) - P_{\text{deal\_in}}(D_i) \times \text{Loss}_{\text{deal\_in}} - P_{\text{exhaustive}} \times \text{Penalty}_{\text{noten}}$$

- $P_{\text{win}}$: 有効牌の受入れ枚数、残り巡目、向聴数に応じた和了確率
- $\text{Score}_{\text{win}}$: 和了時の推定飜数（確定役＋ドラ＋高目安目の加重平均）に基づく平均打点
- $P_{\text{deal\_in}}$: 捨て牌 $D_i$ の危険度（現物、筋、字牌、無筋の統計的放銃確率モデル）

### Rayon による並列探索
手牌に存在する最大14種類の打牌選択肢のシミュレーション・期待値計算を、`rayon::prelude::*` を用いてマルチコア CPU 上で並列実行します。
これにより、1回の打牌選択検討をミリ秒未満（サブミリ秒）で完了します。

## 6. 着順分布推定 & 順位点 (Placement EV) モデル

### 局収支から順位点への変換
麻雀の最終目標は「素点」ではなく「順位点（ウマ・オカ）」の最大化です。
`Placement EV` モデルは、現在の各家持ち点 $S = [s_0, s_1, s_2, s_3]$ と残り局数から、局終了後の点数変動 $\Delta S$ に対する**最終着順確率分布**をシグモイド／多項ロジットモデルにより推定します。

$$P(\text{Rank} = k \mid S + \Delta S)$$

### 順位点期待値
ルール設定（Mリーグルール: `[+50, +10, -10, -30]` など）の順位点ベクトル $U$ に対し：

$$\text{PlacementEV} = \sum_{k=1}^4 P(\text{Rank} = k) \times U_k$$

これにより、「ラス回避優先」「トップ維持」「素点よりも着順浮上」といった実戦的な局面判断（押し引き・着順配慮打牌）をAIが自動的に選択します。

## 7. オーラス逆転条件逆算アルゴリズム

### 条件網羅探索
南4局（オーラス）において、指定着順（例: 2位から1位）へ浮上するための条件を以下の3軸で逆算：
1. **ツモ和了**:
   - 子ツモの場合: 他家全員から点数を徴収するため、点差は直撃の約半分で届く。
   - 親ツモの場合: 連荘による継続判定を含め計算。
2. **直撃（ターゲット家からのロン）**:
   - 着順ターゲット（トップ目など）から直撃した場合、点差が $2 \times \text{和了点}$ 縮まるため、最小打点で逆転可能。
3. **脇ロン（他家からのロン）**:
   - ターゲット以外の他家から出和了した場合の必要点数。

アルゴリズムは、供託リーチ棒・本場（1本場あたり300点または場300点）を正確に加味し、必要な「飜数・符（例: 2飜40符、満貫、跳満）」の最小条件リストを返します。

## 8. 鳴きアドバイザー & 牌譜レビュー評価モデル

### 鳴き判断（CallAdvisor）
他家が牌を切った瞬間、以下の2つの状態の EV を比較：
- $EV_{\text{call}}$: 鳴いて手牌を進行させた場合の期待値（門前役消滅・守備牌減少のペナルティ含む）
- $EV_{\text{pass}}$: スルーして門前を維持した場合の期待値

$$\Delta EV_{\text{call}} = EV_{\text{call}} - EV_{\text{pass}}$$

$\Delta EV_{\text{call}} > 0$ かつ閾値を超えた場合にチー・ポン・カンを推奨します。

### 牌譜レビュー & 悪手判定
プレイヤーの実打牌 $D_{\text{actual}}$ と AI 最適打牌 $D_{\text{best}}$ の EV 差（EV Loss）を測定：
- $\Delta EV < 150$: **好手 / 許容手 (Acceptable)**
- $150 \le \Delta EV < 500$: **疑問手 (Inaccuracy)**
- $500 \le \Delta EV < 1500$: **悪手 (Mistake)**
- $\Delta EV \ge 1500$: **大悪手 (Blunder)**

1局全体の累積損失 EV と各巡目の悪手原因を抽出し、客観的な実力評価とフィードバックを提供します。
